JOIN 심화 & 서브쿼리 심화 사용 DB: chinook.db (SQLite Tutorial 샘플 DB) 1. JOIN 심화 1) EQUI JOIN / Non EQUI JOIN EQUI JOIN: = 연산자로 연결하는 등가 조인. 기본키-외래키 관계에서 주로 사용. Non EQUI JOIN: >, <, BETWEEN 등 비등가 연산자를 사용하는 조인. -- EQUI JOIN (WHERE 절) SELECT al.Title AS AlbumTitle, ar.Name AS ArtistName FROM albums al, artists ar WHERE al.ArtistId = ar.ArtistId ORDER BY al.Title; -- Non EQUI JOIN (재생시간 비교) SELECT t1.Name AS LongTrack, t1.Milliseconds AS LongMs, t2.Name AS ShortTrack, t2.Milliseconds AS ShortMs FROM tracks t1, tracks t2 WHERE t1.AlbumId = t2.AlbumId AND t1.Milliseconds >= 300000 AND t2.Milliseconds < t1.Milliseconds; 2) INNER JOIN (ON / USING / NATURAL) ON: 컬럼명이 달라도 사용 가능, 가장 일반적인 형태. USING: 동일한 이름의 컬럼에 사용. 별칭(alias) 사용 불가. NATURAL: 이름이 같은 모든 컬럼을 자동으로 등가 조인 조건으로 사용. 별칭 및 추가 조건(ON/USING/WHERE) 불가. -- ON 절 SELECT t.Name AS TrackName, g.Name AS GenreName FROM tracks t INNER JOIN genres g ON t.GenreId = g.GenreId; -- USING 절 (별칭 금지) SELECT albums.Title AS AlbumTitle, artists.Name AS ArtistName FROM albums INNER JOIN artists USING (ArtistId); -- NATURAL JOIN (공통 컬럼 자동 매칭, 별칭 금지) SELECT albums.Title AS AlbumTitle, artists.Name AS ArtistName FROM albums NATURAL JOIN artists; 3) CROSS JOIN 조인 조건 없이 두 테이블의 모든 행 조합(카테시안 곱) 생성. 결과 행 수 = 테이블A 행 수 × 테이블B 행 수. SELECT g.Name AS GenreName, m.Name AS MediaTypeName FROM genres g CROSS JOIN media_types m; 4) OUTER JOIN (LEFT / RIGHT / FULL) 종류 설명 SQLite 지원 LEFT OUTER JOIN 왼쪽 테이블 모든 행 보존, 불일치는 NULL 항상 지원 RIGHT OUTER JOIN 오른쪽 테이블 모든 행 보존 SQLite 3.39.0 이상 FULL OUTER JOIN 양쪽 모두 보존 SQLite 3.39.0 이상 버전 확인: SELECT sqlite_version(); 구버전 대안: RIGHT JOIN → 테이블 순서 바꿔 LEFT JOIN / FULL JOIN → LEFT JOIN UNION RIGHT JOIN -- LEFT JOIN: 앨범 없는 아티스트도 포함 SELECT ar.Name AS ArtistName, al.Title AS AlbumTitle FROM artists ar LEFT JOIN albums al ON ar.ArtistId = al.ArtistId; -- "없는 데이터" 찾기: LEFT JOIN + IS NULL SELECT ar.Name AS ArtistName FROM artists ar LEFT JOIN albums al ON ar.ArtistId = al.ArtistId WHERE al.AlbumId IS NULL; -- RIGHT JOIN → LEFT JOIN 변환 (테이블 순서 교체) SELECT g.Name AS GenreName, COUNT(t.TrackId) AS TrackCount FROM genres g LEFT JOIN tracks t ON g.GenreId = t.GenreId GROUP BY g.GenreId, g.Name; -- FULL OUTER JOIN 대체 (구버전): UNION SELECT ar.Name AS ArtistName, al.Title AS AlbumTitle FROM artists ar LEFT JOIN albums al ON ar.ArtistId = al.ArtistId UNION SELECT ar.Name AS ArtistName, al.Title AS AlbumTitle FROM artists ar RIGHT JOIN albums al ON ar.ArtistId = al.ArtistId; ON vs WHERE (OUTER JOIN에서 중요) ...

0610 SQL 심화 (집계 함수, 집합 연산자, 계층형)

🗄️ 오후 수업 요약 | SQL 심화 — 집계 함수 / 서브쿼리 심화 / 집합 연산자 / 계층형 질의 날짜: 2026-06-10 PART 1. 집계 함수 (Aggregate Functions) 개념: 여러 행(row)을 입력받아 단일 값 하나를 반환하는 함수. GROUP BY, HAVING과 함께 쓰는 것이 핵심 패턴. COUNT — 행 수 세기 -- 앨범별 트랙 수 (많은 순) -- 생각 흐름: "앨범마다 트랙이 몇 개씩?" → AlbumId로 묶고 → TrackId 개수 셈 SELECT AlbumId, COUNT(TrackId) AS track_count FROM tracks GROUP BY AlbumId ORDER BY track_count DESC; -- DISTINCT 조합: 실제로 구매한 고유 고객 수 -- 생각 흐름: 같은 고객이 여러 번 구매해도 1명으로 세야 함 → DISTINCT 필요 SELECT COUNT(DISTINCT CustomerId) AS 구매고객수 FROM invoices; SUM — 합계 -- 연도별 총 매출 -- 생각 흐름: InvoiceDate에서 연도만 뽑아 → 그걸로 묶고 → Total 합산 SELECT strftime('%Y', InvoiceDate) AS 연도, ROUND(SUM(Total), 2) AS 연매출 FROM invoices GROUP BY 연도 ORDER BY 연도; -- strftime('%Y', 날짜컬럼) : 날짜에서 연도(4자리)만 추출하는 SQLite 함수 AVG — 평균 -- 고객 1인당 평균 청구 금액 -- 생각 흐름: invoices 테이블의 Total 전체 평균 → 단순 AVG 한 번으로 끝 SELECT ROUND(AVG(Total), 2) AS 평균청구금액 FROM invoices; MAX / MIN — 최댓값 / 최솟값 -- 고객별 최대·최소·평균 청구 금액 한 번에 -- 생각 흐름: 고객마다 여러 청구서가 있음 → CustomerId로 묶고 → 세 값 동시 계산 SELECT CustomerId, ROUND(MAX(Total), 2) AS 최대청구, ROUND(MIN(Total), 2) AS 최소청구, ROUND(AVG(Total), 2) AS 평균청구 FROM invoices GROUP BY CustomerId ORDER BY 최대청구 DESC; GROUP_CONCAT — 문자열 연결 -- 앨범 1번의 트랙 이름들을 ' / ' 구분자로 한 줄에 연결 -- 생각 흐름: 여러 행의 문자열 값을 하나로 합치고 싶을 때 사용 SELECT GROUP_CONCAT(Name, ' / ') AS 트랙목록 FROM tracks WHERE AlbumId = 1; -- 결과 예: "For Those About To Rock / Put The Finger On You / ..." HAVING — 집계 후 그룹 필터링 -- WHERE vs HAVING 비교 -- WHERE : 집계 이전, 개별 행 단위 필터 (집계함수 사용 불가) -- HAVING : 집계 이후, 그룹 단위 필터 (집계함수 사용 가능) -- 총 매출이 $40 이상인 고객 -- 생각 흐름: 먼저 고객별로 묶어 SUM → 그 결과에 조건 적용 → HAVING 필요 SELECT CustomerId, ROUND(SUM(Total), 2) AS 총매출 FROM invoices GROUP BY CustomerId HAVING 총매출 >= 40 ORDER BY 총매출 DESC; PART 2. 서브쿼리 심화 복습: 서브쿼리 = SQL 안에 또 다른 SELECT. 위치에 따라 역할이 달라집니다. ...
