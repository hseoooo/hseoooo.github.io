JOIN 심화 & 서브쿼리 심화#

사용 DB: chinook.db (SQLite Tutorial 샘플 DB)

1. JOIN 심화#

1) EQUI JOIN / Non EQUI JOIN#

  • EQUI JOIN: = 연산자로 연결하는 등가 조인. 기본키-외래키 관계에서 주로 사용.
  • Non EQUI JOIN: >, <, BETWEEN 등 비등가 연산자를 사용하는 조인.
-- EQUI JOIN (WHERE 절)
SELECT al.Title AS AlbumTitle, ar.Name AS ArtistName
FROM albums al, artists ar
WHERE al.ArtistId = ar.ArtistId
ORDER BY al.Title;

-- Non EQUI JOIN (재생시간 비교)
SELECT t1.Name AS LongTrack, t1.Milliseconds AS LongMs,
       t2.Name AS ShortTrack, t2.Milliseconds AS ShortMs
FROM tracks t1, tracks t2
WHERE t1.AlbumId = t2.AlbumId
  AND t1.Milliseconds >= 300000
  AND t2.Milliseconds <  t1.Milliseconds;

2) INNER JOIN (ON / USING / NATURAL)#

  • ON: 컬럼명이 달라도 사용 가능, 가장 일반적인 형태.
  • USING: 동일한 이름의 컬럼에 사용. 별칭(alias) 사용 불가.
  • NATURAL: 이름이 같은 모든 컬럼을 자동으로 등가 조인 조건으로 사용. 별칭 및 추가 조건(ON/USING/WHERE) 불가.
-- ON 절
SELECT t.Name AS TrackName, g.Name AS GenreName
FROM tracks t
INNER JOIN genres g ON t.GenreId = g.GenreId;

-- USING 절 (별칭 금지)
SELECT albums.Title AS AlbumTitle, artists.Name AS ArtistName
FROM albums
INNER JOIN artists USING (ArtistId);

-- NATURAL JOIN (공통 컬럼 자동 매칭, 별칭 금지)
SELECT albums.Title AS AlbumTitle, artists.Name AS ArtistName
FROM albums
NATURAL JOIN artists;

3) CROSS JOIN#

  • 조인 조건 없이 두 테이블의 모든 행 조합(카테시안 곱) 생성.
  • 결과 행 수 = 테이블A 행 수 × 테이블B 행 수.
SELECT g.Name AS GenreName, m.Name AS MediaTypeName
FROM genres g
CROSS JOIN media_types m;

4) OUTER JOIN (LEFT / RIGHT / FULL)#

종류 설명 SQLite 지원
LEFT OUTER JOIN 왼쪽 테이블 모든 행 보존, 불일치는 NULL 항상 지원
RIGHT OUTER JOIN 오른쪽 테이블 모든 행 보존 SQLite 3.39.0 이상
FULL OUTER JOIN 양쪽 모두 보존 SQLite 3.39.0 이상
  • 버전 확인: SELECT sqlite_version();
  • 구버전 대안: RIGHT JOIN → 테이블 순서 바꿔 LEFT JOIN / FULL JOIN → LEFT JOIN UNION RIGHT JOIN
-- LEFT JOIN: 앨범 없는 아티스트도 포함
SELECT ar.Name AS ArtistName, al.Title AS AlbumTitle
FROM artists ar
LEFT JOIN albums al ON ar.ArtistId = al.ArtistId;

-- "없는 데이터" 찾기: LEFT JOIN + IS NULL
SELECT ar.Name AS ArtistName
FROM artists ar
LEFT JOIN albums al ON ar.ArtistId = al.ArtistId
WHERE al.AlbumId IS NULL;

-- RIGHT JOIN → LEFT JOIN 변환 (테이블 순서 교체)
SELECT g.Name AS GenreName, COUNT(t.TrackId) AS TrackCount
FROM genres g
LEFT JOIN tracks t ON g.GenreId = t.GenreId
GROUP BY g.GenreId, g.Name;

-- FULL OUTER JOIN 대체 (구버전): UNION
SELECT ar.Name AS ArtistName, al.Title AS AlbumTitle
FROM artists ar LEFT JOIN albums al ON ar.ArtistId = al.ArtistId
UNION
SELECT ar.Name AS ArtistName, al.Title AS AlbumTitle
FROM artists ar RIGHT JOIN albums al ON ar.ArtistId = al.ArtistId;

ON vs WHERE (OUTER JOIN에서 중요)

  • ON 조건: 조인 조건 — 불일치 행도 NULL로 포함됨
  • WHERE 조건: 조인 후 필터링 — NULL 행도 제거됨
  • “짝이 없는 행"을 찾으려면 WHERE 오른쪽테이블.키컬럼 IS NULL 패턴 사용

5) 셀프 조인 (Self Join)#

  • 동일 테이블을 두 번 사용, 반드시 별칭(alias) 필요.
  • 계층형 데이터(상사-부하, 카테고리 부모-자식) 처리에 유용.
-- 직원-관리자 관계 (계층형 LEFT JOIN 셀프 조인)
SELECT e.FirstName || ' ' || e.LastName AS EmployeeName,
       m.FirstName || ' ' || m.LastName AS ManagerName
FROM employees e
LEFT JOIN employees m ON e.ReportsTo = m.EmployeeId;

-- 같은 앨범 내 트랙 쌍 비교 (중복 제거: t1.TrackId < t2.TrackId)
SELECT t1.Name AS TrackA, t2.Name AS TrackB,
       ABS(t1.Milliseconds - t2.Milliseconds) AS MsDiff
FROM tracks t1
JOIN tracks t2
  ON t1.AlbumId = t2.AlbumId AND t1.TrackId < t2.TrackId
WHERE ABS(t1.Milliseconds - t2.Milliseconds) <= 60000;

6) 복합 JOIN & WHERE 조건 (응용)#

  • 여러 테이블을 연결한 후 WHERE/GROUP BY/집계를 함께 사용하는 종합 패턴.
-- 직원별 담당 고객 수 + 총 인보이스 합계 (다중 LEFT JOIN + 집계)
SELECT e.FirstName || ' ' || e.LastName AS EmployeeName,
       COUNT(DISTINCT c.CustomerId) AS CustomerCount,
       ROUND(SUM(i.Total), 2) AS TotalSales
FROM employees e
LEFT JOIN customers c ON e.EmployeeId = c.SupportRepId
LEFT JOIN invoices  i ON c.CustomerId = i.CustomerId
GROUP BY e.EmployeeId, e.FirstName, e.LastName
ORDER BY TotalSales DESC;

2. 서브쿼리 심화#

1) 동작 방식에 따른 분류#

  • 비연관 서브쿼리 (Un-Correlated): 메인쿼리 컬럼을 참조하지 않음 → 한 번만 실행.
  • 연관 서브쿼리 (Correlated): 메인쿼리 컬럼을 참조 → 메인쿼리 행마다 재실행.
-- 비연관: 평균 단가보다 비싼 트랙
SELECT Name, UnitPrice
FROM tracks
WHERE UnitPrice > (SELECT AVG(UnitPrice) FROM tracks);

-- 연관: 본인 앨범 평균 재생시간보다 긴 트랙
SELECT t.Name, t.Milliseconds
FROM tracks t
WHERE t.Milliseconds > (
    SELECT AVG(t2.Milliseconds)
    FROM tracks t2
    WHERE t2.AlbumId = t.AlbumId   -- 메인쿼리 참조 → 연관
);

-- 연관 EXISTS vs 비연관 IN (결과는 동일)
SELECT t.Name FROM tracks t
WHERE EXISTS (SELECT 1 FROM invoice_items ii WHERE ii.TrackId = t.TrackId);

SELECT t.Name FROM tracks t
WHERE t.TrackId IN (SELECT ii.TrackId FROM invoice_items ii);

2) 반환 데이터 형태에 따른 분류#

① 단일 행 서브쿼리 (Single Row)#

  • 결과가 1행 1컬럼 → =, <, >, <=, >= 사용.
SELECT InvoiceId, CustomerId, Total
FROM invoices
WHERE Total > (SELECT AVG(Total) FROM invoices);

② 다중 행 서브쿼리 (Multi Row)#

  • 결과가 2행 이상 → IN, NOT IN, EXISTS, NOT EXISTS 사용.
  • ALL / ANY는 SQLite 미지원 → MAX/MIN으로 대체.
-- NOT EXISTS: 앨범이 없는 아티스트
SELECT a.Name AS ArtistName
FROM artists a
WHERE NOT EXISTS (SELECT 1 FROM albums al WHERE al.ArtistId = a.ArtistId);

-- ALL 대체(MAX): Rock 최장 트랙보다 긴 모든 트랙
SELECT Name, Milliseconds
FROM tracks
WHERE Milliseconds > (
    SELECT MAX(t.Milliseconds)
    FROM tracks t INNER JOIN genres g ON t.GenreId = g.GenreId
    WHERE g.Name = 'Rock'
);

-- ANY 대체(MIN): Classical 최단 트랙보다 긴 트랙
SELECT Name, Milliseconds
FROM tracks
WHERE Milliseconds > (
    SELECT MIN(t.Milliseconds)
    FROM tracks t INNER JOIN genres g ON t.GenreId = g.GenreId
    WHERE g.Name = 'Classical'
);

③ 다중 컬럼 서브쿼리 (Multi Column)#

  • 서브쿼리가 여러 컬럼 반환 → (col1, col2) IN (서브쿼리) 형태. SQLite 지원.
-- 각 앨범에서 가장 긴 트랙 (AlbumId, MAX(Milliseconds) 쌍)
SELECT Name, AlbumId, Milliseconds
FROM tracks
WHERE (AlbumId, Milliseconds) IN (
    SELECT AlbumId, MAX(Milliseconds)
    FROM tracks
    GROUP BY AlbumId
);

3) 스칼라 서브쿼리 (Scalar Subquery)#

  • 단일 컬럼 + 단일 행을 반환 → SELECT / WHERE / HAVING 절에서 사용 가능.
  • SQLite는 DUAL 테이블이 없으므로 FROM 없이 바로 SELECT 작성 가능.
-- SELECT 절에서 스칼라 서브쿼리 (장르별 트랙 수)
SELECT g.Name AS GenreName,
       (SELECT COUNT(*) FROM tracks t WHERE t.GenreId = g.GenreId) AS TrackCount
FROM genres g;

-- FROM 없이 SELECT (DUAL 대체): 전체 중 Rock 비율
SELECT ROUND(
    CAST((SELECT COUNT(*) FROM tracks t INNER JOIN genres g ON t.GenreId = g.GenreId WHERE g.Name = 'Rock') AS REAL)
    / CAST((SELECT COUNT(*) FROM tracks) AS REAL), 4
) AS RockRatio;

4) 뷰 (VIEW)#

  • 논리적으로만 존재하는 가상 테이블. CREATE VIEW ... AS SELECT ...
  • SQLite는 CREATE OR REPLACE VIEW 미지원 → DROP VIEW IF EXISTS 후 CREATE VIEW 패턴 사용.
  • 뷰를 기반으로 또 다른 뷰를 생성할 수 있음(뷰 위의 뷰).
-- 뷰 생성 (재생성 패턴)
DROP VIEW IF EXISTS view_track_full;
CREATE VIEW view_track_full AS
SELECT t.TrackId, t.Name AS TrackName, al.Title AS AlbumTitle,
       ar.Name AS ArtistName, g.Name AS GenreName
FROM tracks t
INNER JOIN albums  al ON t.AlbumId  = al.AlbumId
INNER JOIN artists ar ON al.ArtistId = ar.ArtistId
INNER JOIN genres  g  ON t.GenreId  = g.GenreId;

-- 뷰를 이용한 집계
SELECT GenreName, COUNT(*) AS TrackCount
FROM view_track_full
GROUP BY GenreName;

-- 보안성: 민감 정보 제외한 뷰
DROP VIEW IF EXISTS view_customer_public;
CREATE VIEW view_customer_public AS
SELECT CustomerId, FirstName || ' ' || LastName AS CustomerName, Country, Email
FROM customers;

-- 뷰 위에 뷰 생성
DROP VIEW IF EXISTS view_customer_by_country;
CREATE VIEW view_customer_by_country AS
SELECT Country, COUNT(*) AS CustomerCount
FROM view_customer_public
GROUP BY Country;

핵심 요약 표#

구분 핵심 키워드 주의사항
EQUI / Non EQUI = vs >,<,BETWEEN -
INNER JOIN ON / USING / NATURAL USING·NATURAL은 별칭 금지
CROSS JOIN 카테시안 곱 행수 = A×B
LEFT/RIGHT/FULL OUTER JOIN RIGHT/FULL은 SQLite 3.39.0+ 필요
셀프 조인 별칭 필수 계층 구조에 유용
비연관/연관 서브쿼리 메인쿼리 컬럼 참조 여부 EXISTS=연관, IN=비연관
단일/다중 행 서브쿼리 = vs IN/EXISTS ALL→MAX, ANY→MIN 대체
다중 컬럼 서브쿼리 (col1,col2) IN (...) SQLite 지원
스칼라 서브쿼리 SELECT/WHERE/HAVING DUAL 없음, FROM 생략 가능
VIEW CREATE VIEW OR REPLACE 미지원 → DROP 후 재생성
